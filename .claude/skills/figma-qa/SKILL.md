# Проверка страницы по Figma: тестировщик + ревьюер

Аргументы: `$ARGUMENTS` — URL страницы и одна или несколько ссылок Figma с `node-id`
(по фрейму на каждую ширину экрана). Если чего-то не хватает — спроси пользователя.

1. Создай папку запуска `RUN_DIR=qa-reports/<ГГГГ-ММ-ДД>-<короткое имя страницы>/`.
2. **Раунд N = 1.** Запусти агента `figma-qa-tester` (Agent, `subagent_type: figma-qa-tester`,
   `run_in_background: false`) с промптом: PAGE_URL, FIGMA_URL(ы), RUN_DIR, номер раунда.
3. Когда он закончит — запусти агента `figma-qa-reviewer` с теми же PAGE_URL, FIGMA_URL, RUN_DIR
   и номером раунда. Не передавай ревьюеру выводы тестировщика — только пути к файлам,
   чтобы проверка была независимой.
4. Прочитай `RUN_DIR/review.json`.
   - `verdict: PASS` → шаг 5.
   - `verdict: FAIL` и N < 3 → сохрани копию `review.json` как `review-round-N.json`,
     N = N + 1, снова запусти `figma-qa-tester` с указанием «повторный раунд: исправь по
     RUN_DIR/review.json», затем снова ревьюера. Повтори шаг 4.
   - `verdict: FAIL` и N = 3 → шаг 5 с пометкой, что ревьюер не принял работу.
5. Убедись, что `bug-list.xlsx` собран с `--review` (лист «Баг-лист» содержит колонку
   «Проверка ревьюера»). Сообщи пользователю: путь к Excel, сколько багов по серьёзности,
   итог ревьюера и сколько раундов понадобилось, что осталось непроверенным.
